## 판단

첫 검증은 실측 치수·무게가 등록된 단단한 직육면체 블록, 베이스 정지 촬영, 제한된 집기 방향, 한 층 배치로 한다. 다양한 크기를 지원하되 임의 물체의 모든 속성을 단일 영상에서 알아내는 기능으로 정의하지 않는다. 기계 탑재·전도·전원·도달 가능성은 [별도 제원 조사](2026-09-12-pinky-omx-mounting-spec-research.md)의 선행 게이트다.

## 기존 로컬 경계와 새 제안 구분

읽은 근거는 `AGENTS.md`, `docs/AGENTS.md`, `docs/plans/AGENTS.md`, [기존 비전 설계](2026-09-05-vision-accelerator-shield-design.md), `src/rosy_core/rosy_core/node.py`, `bridge/ros_bridge.py`다. 로컬 계약·코드는 실물 설치 증거가 아니다.

- 외부 API는 rosy_core만 담당한다. 웹·Fleet에 raw ROS를 노출하지 않는다.
- node.py에서 FastAPI/uvicorn과 rclpy MultiThreadedExecutor 구성을 확인했다. 같은 프로세스 경계를 유지한다.
- 영상 전처리·추론은 CORE 밖의 비전 프로세스에 둔다. 기존 설계의 rosy-vision은 hardware 위 선택 스택 제안이며 전체 구현 완료를 뜻하지 않는다.
- cmd_vel은 Command Manager만 발행한다. ros_bridge.py의 1/50초 타이머는 실제 주기 지터 보장이 아니다.
- 암 명령 소유권·작업 실행권은 추가 설계 대상이다. 비전이 직접 모터·암을 구동하지 않는다.
- 기존 9월 5일 문서의 당시 기능 부재 서술은 현재 전체 저장소 상태로 재사용하지 않는다. 제한된 파일과 파일명 검색을 확인했으며 배포 상태는 조사하지 않았다.

아래 단계명·데이터는 제안이며 기존 REST 경로·API 필드·승인 ADR이 아니다.

## 영상에서 얻을 수 있는 정보

OpenCV solvePnP는 알려진 3D 점과 영상 대응 점, 내부 보정값으로 자세를 구한다. 임의 박스의 크기를 자동으로 알아내는 함수가 아니다. [공식 PnP](https://docs.opencv.org/4.x/d5/d1f/calib3d_solvePnP.html)

| 조건 | 가능한 접근 | 제한 |
|---|---|---|
| 등록 치수·마커 블록 | 마커/모서리 + PnP | 대칭·가림·평면 자세 모호성, 마커 장착 변환 필요 |
| 알려진 평면 + RGB 보정 | 광선-평면 교점 | 그 평면 위 점만 유효. 박스 상단을 바닥으로 투영하면 오류 |
| 깊이/스테레오 | 표면 점군·박스 모델 추정 | 최소 거리·반사·가림·숨은 면 평가 필요 |
| 크기 미상 단일 RGB | 검출 후보와 추가 관측 | 별도 척도 없이 절대 크기·거리 확정 불가 |

단안 척도 모호성에 근거하면 2D 검출만으로 3D 치수·무게·내부 무게중심·압축강도·지지력을 확정할 수 없다. 깊이 센서도 무게를 제공하지 않는다. 등록 치수, 저울 실측, 적층 허용 정책이 따로 필요하다.

OpenCV는 내부 보정·왜곡 보정·hand-eye 계산을 제공한다. 리사이즈 시 내부 행렬 조정이 필요하다. [공식 calib3d](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)

제안: 크롭·리사이즈·letterbox 역변환, 해상도·초점·장착 버전을 보존한다. 손목 카메라는 촬영 시점 관절 자세와 hand-eye 변환을 연결하고 고정 카메라는 베이스-카메라 변환을 검증한다. 보정 자료와 평가 표적을 분리해 바닥·트레이·적층 상단에서 실제 mm 오차를 측정한다. 재투영 오차만으로 집기 정확도를 승인하지 않는다.

## 촬영부터 놓기까지 제안 흐름

| 단계 | 수행 | 필요한 증거 |
|---|---|---|
| 준비 | 베이스 정지·암 실행권·보정 확인 | 현재 상태 |
| 촬영 | 노출·취득 시각·광학 좌표계 기록, 큐 제한 | 시각이 있는 프레임 |
| 전처리 | 왜곡·ROI·색상·크기 처리 | 역변환·보정 버전 |
| 인식 | 마커·점·윤곽 또는 지원 모델 추론 | 대응 점·품질 |
| 공간 변환 | PnP/깊이/알려진 평면 | metric pose·치수 출처·불확실성 |
| 후보 선택 | 그리퍼 폭·접근·적재 슬롯 | 물체·슬롯 예약 |
| 계획 | 실제 베이스·암·적재물 충돌 모델 | 접근·집기·후퇴 가능성 |
| 실행 | 궤적·그리퍼, 취소·오류 감시 | 실제 관절·그리퍼 상태 |
| 확인 | 들림·그리퍼 잔류·놓인 위치 확인 | 성공/실패/불확실 |
| 갱신 | 물체·빈 공간 갱신, 재계획 | 다음 시작 상태 |

관측 취득 시각·좌표계·보정/모델 버전·품질을 연결한다. 최신 TF를 무조건 쓰지 않고 촬영 시각에 맞는 변환을 요구하도록 설계한다. TF 누락·timestamp 불일치·오래된 관측은 재촬영한다. tf2 공식 페이지는 이번 접근에서 차단되었으므로 구체 API 호출 형태는 미검증이며 이 내용은 설계 요구다.

도착 후 재측정하고 집기 중 베이스를 고정한다. 최대 관측 나이·정지 기준·허용 오차는 블록·그리퍼·적층 간극을 정한 뒤 오차 예산으로 고정한다. 통신 단절 시 암 토크를 일괄 끄는 정책을 추정하지 않는다. 실제 컨트롤러의 정지·자세 유지 동작 확인이 필요하다.

## ROS 조작 스택

MoveIt Planning Scene은 로봇 상태·충돌·제약 검사를 제공한다. 베이스·LiDAR·브래킷·적재함·적재 박스·팔레트를 통합 모델에 넣는 것이 제안이다. 충돌 검사는 전도·하중·접촉의 증명이 아니다. [공식 Planning Scene](https://moveit.picknik.ai/main/doc/examples/planning_scene/planning_scene_tutorial.html)

Task Constructor는 집기·놓기를 단계로 분해해 후보를 연결하는 계획 기능이다. ROSY 작업 관리자 아래의 구현 후보이며 테트리스 배치 최적화나 실제 집기 성공 확인까지 자동 제공하지 않는다. [공식 튜토리얼](https://moveit.picknik.ai/main/doc/tutorials/pick_and_place_with_moveit_task_constructor/pick_and_place_with_moveit_task_constructor.html)

ros2_control Controller Manager는 하드웨어 읽기·컨트롤러 갱신·명령 쓰기와 생명주기를 관리한다. 실제 주기는 OS·드라이버 영향을 받으므로 Pi 실측이 필요하다. [Jazzy 공식 문서](https://control.ros.org/jazzy/doc/ros2_control/controller_manager/doc/userdoc.html)

OMX 선택 뒤 제조사 ROS 배포판·ARM64 의존성·URDF/SRDF·관절 제한·IK·그리퍼·취소·단절 동작을 확인한다. main/rolling MoveIt 문서는 기능 근거이며 Jazzy 조합의 호환성 보장이 아니다. Pinky 주행을 ros2_control로 교체하는 범위는 포함하지 않는다.

## Pi 카메라·가속기

공식 Pi 카메라 환경은 libcamera 도구·Picamera2 경로를 제공한다. Pinky 특정 5MP 카메라의 센서·UVC/CSI 버스·드라이버·컨테이너 호환성은 제원만으로 확정되지 않는다. 실물 식별과 취득 timestamp·해상도·노출 제어 검증이 필요하다. [공식 카메라](https://www.raspberrypi.com/documentation/computers/camera_software.html)

AI HAT+는 Hailo-8L 13 TOPS 또는 Hailo-8 26 TOPS INT8 추론을 지원한다. 공식 문서는 AI Kit를 생산 종료로 표시한다. 기존 9월 5일 AI Kit 후보를 구매 근거로 그대로 사용하지 않는다. [공식 AI HAT](https://www.raspberrypi.com/documentation/accessories/ai-hat-plus.html)

공식 현행 목록에는 AI HAT+ 2의 Hailo-10H 40 TOPS(INT4)도 있다. INT8 수치와 직접 비교하거나 더 높은 TOPS만으로 선택하지 않는다. 어느 보드도 이번 작업에서 장착·성능 검증하지 않았다.

CPU·GPU·NPU는 같은 실행 자원이 아니다. NPU 지원 모델 추론을 OpenCV 전 연산·PnP·MoveIt 자동 가속으로 확대하지 않는다. GPU도 연산·빌드·드라이버 확인이 필요하다. ROS 설치·8GB·TOPS는 통합 성능을 보장하지 않는다.

CPU의 알려진 블록 인식을 기준선으로 잡고 추론이 병목일 때 가속기를 비교한다. 촬영부터 판정까지 지연·메모리 전송·열·전력을 합쳐 평가한다. HAT 공간·냉각·배선·전원과 기존 보드 간섭을 검토한다. 비전 과부하 때 프레임률·큐를 먼저 제한하고 CORE 제어 경로를 보호한다. 원격 오프로딩은 온디바이스 요구를 바꾸는 별도 선택이다.

## 예정 벤치 행렬

이번 조사에서는 실행하지 않았다. 임계값은 기계·블록 허용치 확정 후 고정한다. 반복 수·p50/p95/p99·최댓값·실패 원인을 함께 기록한다.

| 시험 | 비교 | 측정 | 승인 조건 |
|---|---|---|---|
| 촬영 | 해상도·노출·조명·작업 높이 | FPS·취득 지연·가림·블러 | 전 작업 영역 관측 |
| 좌표 | 거리·방향·가장자리·독립 표적 | mm·각도 오차·모호성 | 집기·배치 오차 예산 충족 |
| 처리 | CPU/지원 가속 | 전처리·추론·전송·TF·전체 지연 | 유효시간 내 결과 |
| 계획 | 빈/부분 적재·바닥/트레이/팔레트 | 계획시간·IK 실패·경로 여유 | 접근·놓기·후퇴 가능 |
| 통합 | 주행·비전·계획·웹 미리보기 | cmd_vel 간격·정지 응답·CPU/RSS·열·전압 | 기존 제어·정지 조건 유지 |

| 복구 | stale 영상·TF 누락·연결 단절·취소 | 거절·정지·유지·중복 실행 | 검증된 상태에서만 재개 |

시뮬레이션, 고정 벤치, 탑재 정지, 이동 후 집기, 적층은 별도 증거 단계다. 다음 입력은 정확한 OMX 모델·카메라 식별·블록 실측표·장착 도면·트레이/팔레트 크기·첫 적층 높이다. 코드·API·ADR 변경, Pi 벤치, 하드웨어 연결·구동은 수행하지 않았다.
