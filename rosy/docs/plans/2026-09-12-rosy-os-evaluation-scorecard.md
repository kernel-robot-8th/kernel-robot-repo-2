# ROSY OS 평가표와 유지보수 목표

> 2026-09-13 편입 안내: 이 문서는 작성 당시의 조사·평가 근거다. 현재 제품 경계와 구현 순서는 [ADR D-37~D-44](../reference/ROSY%20ADR%20Log.md), [흡수 실행 계획](2026-09-12-rosy-control-absorption-plan.md), [최신 실행 결과](2026-09-12-control-absorption-results.md)를 우선한다. 조사 당시의 미실행·별도 Control 표기는 현재 배포 상태를 뜻하지 않는다.
작성일: 2026-09-12. 상태: 초기 목표안. 아래 숫자는 달성 실적·보증·SLA가 아니다.

## 1. 판정 방법
평가 대상은 [모듈 설계](2026-09-12-rosy-os-module-evaluation-maintenance-design.md)의 M01–M14다. 현재 [소스 기준선](2026-09-12-rosy-os-module-evidence-baseline.md)은 소스와 테스트 파일 존재만 확인했다. 이번 작업에서 런타임·시뮬레이션·장치 시험은 실행하지 않았다.

| 판정 | 의미 |
|---|---|
| GO | 해당 프로파일의 명시된 기준을 필요한 실행 증거로 충족 |
| HOLD | 필수 기능·수치·증거가 없거나 실패 |
| PARKED | 합의한 이후 단계로 연기; 현재 프로파일 범위 밖 |
| N/A | 해당 프로파일에서 제외한 사유·책임자 기록이 있음 |

증거는 SOURCE(소스), LOCAL(로컬 실행), SIM(시뮬레이션), BENCH(통제된 실물), FIELD(현장)로 구분한다. 모듈 특성상 불필요한 증거 단계는 사유를 남긴다. 단순 가중 평균으로 안전·물리 제약 실패를 상쇄하지 않는다. 시험 파일 존재는 LOCAL 통과가 아니다.

## 2. 모듈별 평가 카드
각 모듈마다 아래 항목을 한 장의 기록으로 유지한다. 현재 모든 실행 결과는 NOT RUN이다.

| 항목 | 기록할 값 |
|---|---|
| 대상 | 모듈 ID, 프로파일, 주 담당/대리, 검토자 |
| 실행 조건 | 장치·OMX 모델·펌웨어, 전원, 박스 치수/질량, 조명·바닥·적재 조건 |
| 버전 | 소스 SHA, 이미지 digest, bundle, 설정·보정·모델 버전 |
| 계약 | 입력·출력·단위·시간 기준·준비 조건·권한·오류·취소 |
| 기준 | 허용 오차·최대 지연·실패/복구 동작, 근거, 결정 담당자 |
| 실행 증거 | 날짜, 재현 명령/절차, 원시 로그·영상 위치, 반복 횟수 |
| 결과 | 성공/실패/미실행 횟수, 지연 p50/p95/max, 측정 불확도, 예외 |
| 유지보수 | 고장 탐지→진단→복구→재인수 절차, 부품·도구·권한 |
| 판정 | GO/HOLD/PARKED/N/A, 미해결 항목, 다음 실행 책임자 |

샘플 수가 작은 p95는 참고값이다. 원시 값과 최댓값을 함께 남긴다. 실패 시험을 제외하고 성공률을 계산하지 않는다. 작업 재시도는 최초 성공과 분리하여 기록한다.

## 3. 제안하는 공통 목표
| 목표 | 초기 기준 제안 | 조건·측정 / 담당 |
|---|---|---|
| 유지보수 소유권 | 인수 대상 모듈 100% 주 담당·대리·runbook 지정 | 미지정 모듈 인수 HOLD / 각 모듈 책임자 |
| 계약 추적 | 필수 입력·출력·설정·오류·취소 시나리오 100% 기록 | 분모는 릴리스별 시나리오 목록으로 고정 / CORE·통합 |
| 기능 광고 | 미구현·미준비 기능의 실행 가능 오표시 0건 | 부팅·단절·재연결 음성 시나리오 전수 / CORE |
| 명령·관측 유효성 | 명시한 중복·만료·권한 위반 시험 모두 기대대로 처리 | 미정인 만료값은 통과 처리 불가 / 제어 |
| 진단 수집 | 유효한 수집 요청부터 묶음 생성까지 2분 이내 | 저장공간·로그 상한을 고정한 BENCH, 비밀정보 제외 / 운영 |
| 알려진 고장 분류 | 진단 묶음 접수부터 고장 분류까지 10분 이내 | 사전 등록 고장군, 담당자 근무 조건; 신규 고장 해결시간 아님 / 운영 |
| 런타임 복구 | rollback 개시부터 core 건강 확인까지 10분 이내 | 호환 이전 bundle·전원·저장장치 정상, 구동 재승인 제외 / 릴리스 |
| SD 교체 복구 | 정비 시작부터 core 건강 확인까지 30분 이내 | 검증된 예비 SD·신원 복구 수단·작업자 준비, 기구 수리 제외 / 플랫폼 |
| 초기 반복 운용 | 프로파일·조건별 20회 연속 업무 시험 | 초기 디버깅 gate이며 신뢰성 인증 아님; 중대 제약 위반 0건 / 통합 |
| 지속 운용 관찰 | 목표 부하로 2시간 관찰 시험 | 온도·메모리·프레임 지연 기록; 장기 수명·배터리 목표 대체 불가 / 플랫폼 |

위 시간 목표는 첫 BENCH 결과로 실현 가능성을 검토한다. 기준을 변경하면 이유·버전·재시험 범위를 남긴다. 결과를 본 뒤 실패를 감추기 위해 소급 변경하지 않는다.

## 6. 단계별 목표와 출시 조건
1. **R0 기준선:** 모듈 소유권·프로파일·누락 수치·장치 인벤토리를 확정한다. 현재 결과는 문서 초안과 소스 조사까지다.
2. **R1 공통 플랫폼:** P0의 기능 준비·권한·명령 소유권·진단·복구를 실제 Pi에서 검증한다.
3. **R2 작업 통합:** 선정 OMX를 고정한 P1에서 등록 블록 집기·배치·실패 복구를 검증하고 P2 인계로 확장한다.
4. **R3 모바일 암:** 물리 탑재 gate를 닫은 후 P3 도달·정지·운반·적층을 검증한다. P2는 중간 검증 구성이지 최종 요구의 대체가 아니다.

각 단계는 일정 약속이 아닌 의존 순서다. 출시에는 필수 모듈 계약과 해당 증거, 전체 업무 결과, 고장 복구, 유지보수 담당·절차가 모두 필요하다. 소스 merge·이미지 발행·장치 설치·현장 인수는 각각 기록한다. 현재 하드웨어 선정·탑재와 실행 검증이 남아 있어 제품 인수는 HOLD다.

## 7. 첫 실행 백로그
- 플랫폼: Pi 이미지·bundle·장치 식별 기준선과 P0 재현 절차 확보.
- 기구/전장: Pinky 적재·체결·전원 자료 확인 및 OMX 후보별 실측 목록 준비.
- 비전/조작: 등록 블록군·좌표 오차 예산·집기 결과 관측 방법 정의.
- 작업 앱: 단계 상태·취소·중복·재부팅 후 물체 재확인 시나리오 정의.
- 운영/릴리스: 진단·rollback·SD 교체 runbook 작성 후 시간 목표 실측.

이 백로그는 후속 구현·실험 범위를 구체화하기 위한 것이다. 이 문서 작성으로 장치 제어·구매·배포를 수행한 것은 아니다.


## 현재 코드 재검토 보완
이 문서의 조사 이후 Rosy Control과 OS 내부 Fleet까지 추적하고 선택 로컬 테스트 266개를 확인했다. 비전·주행의 기존 구현과 두 명령 경로를 반영한 [현재 구조·수정 계획](2026-09-12-rosy-os-system-architecture-roadmap.md)을 우선 참조한다. 기존 미실행 표시는 최초 조사 시점의 기록이며 실물 통합 인수는 여전히 미확인이다.
