# 연동 상태와 다음 조치 개선

기존 설계25와 HarborLogi Operate 화면을 유지한다. 사용자는 운영 연동의 남은 부분을 개선하도록 요청했다. 연결 설정·신원 확인·ARM 조회 API를 구분하고 마지막 확인 근거와 다음 담당 조치를 표시한다. 조회 성공을 실행 승인이나 현장 수용으로 확대하지 않는다.

- [x] 기존 실패 처리에 DNS·TLS·시간 초과의 실제 예외 형식별 회귀 시험을 추가하고 RED를 확인한다. 원문 예외·주소·토큰은 저장하거나 표시하지 않는다.
- [x] 기존 GET 검사와 설정 fingerprint를 유지하면서 원인 코드를 분류한다. 새 네트워크 설정이나 자동 재검사를 추가하지 않는다.
- [x] guide_pages의 표시 자료와 integration 템플릿에 세 단계·다음 조치를 반영한다. 신원 확인 후 ARM503인 경우 신원 확인 사실과 설치 미준비를 함께 표시한다.
- [x] 기존 전체 웹 시험, 단위 시험, 좁은/넓은 실제 브라우저 화면과 기계적 디자인 검사를 확인한다.
- [ ] 독립 검토, CI·PR·병합, 로컬 반영과 검증 기록을 완료한다. ROSY 병합 대기와 관리자 DNS 확인은 별도로 유지한다.

주요 파일: `harbor_web/fleet_connection.py`는 안전한 오류 분류, `guide_pages.py`는 표시와 조치, `templates/integration.html`은 기존 토큰 기반 화면, `tests/test_fleet_connection.py`는 실제 예외/저장된 상태/읽기 전용 검증을 소유한다. API 계약·역할·Fleet 제출/승인 권한·DB schema는 변경하지 않는다.
