# 저장된 후보 공간 비교 검증

2026-10-26. 기준 main `1a7a860a9cda527fcd174c5b0a61378ee4f622bc`. ADR0014·설계26을 확장한 Harbor 읽기 화면이며 실제 실행/관측 수용을 바꾸지 않는다.

## 확인한 결과

- 후보 목록의 링크와1~5의 유효한 후보 경로에서, 해당 Plan에 저장된 이동과 고정 관측을 사용한다. 후보2는 후보1의 추천 이동과 다른 자기 이동을 표시한다.
- 2D·3D의 기존 선택·다칸 점유·단계·재생·카메라를 재사용한다. 비교 화면은 실행/채택 조작을 제공하지 않는다.
- 조회 전후 Plan·관측·감사·Command 건수와 Plan.result가 동일하다. GET에서 계획 탐색과 Fleet HTTP 호출을 금지한 회귀 시험을 통과했다.
- 익명 접근은 로그인으로 안내하고 field 역할은403, 허용된 viewer/operator/admin은 조회한다. POST405, 범위 밖·없음·HOLD·옛/잘못된 형식404를 확인했다.
- 출발 배치·화물 식별이 틀리거나 다른 화물로 도착하는 저장 이동을 거절한다. 크기 원본·고정 방향, 기존 snapshot의 점유/지지 검증을 유지했다. 지시 변경 경고와 한도 내 추천/최적성 미확정 문구도 확인했다.

## 시험과 화면

최초4개 회귀 시험에서 예상한 실패3건을 확인했다. 독립 검토에서 찾은 malformed JSON과 출발 위치 불일치도 별도 RED로 재현하고 수정했다. 최종 Django 전체207 PASS, 필수 unittest156 실행 OK(opt-in 실제 Fleet 통합 클래스1개 skip)다. skip을 실제 Fleet 실행으로 세지 않는다.

기존 `tools/integration/multicell_browser_check.py`에 후보 비교 경로를 추가해 Edge에서 실행했다. 마지막 하네스 exit0·report PASSED이며1440/1280/768/390px에서 가로 넘침 없이 후보2의 단계가 표시됐다. C1의2×1 점유 연계, 후보1 복귀, 계획 원본 유지와 비교 중 POST0을 확인했다. 기존 카메라·가상 편집·느린 재생·fallback 회귀도 같은 도구에서 통과했다. `runs/candidate-preview-browser-release/run-f561a94d84fd493e8da805fca2ffd929/report.json`은 로컬 근거다.

Windows 리디렉션의 CP1252에서도 CLI가 실패하지 않도록 콘솔 JSON을 ASCII escape로 출력하고 상세 report 파일은 UTF-8로 유지했다. 초기 화면 검사 뒤 뷰어를 점수/원본보다 먼저 보도록 다듬었고, sticky header가 화면 중간에 찍히지 않게 맨 위로 이동한 뒤 캡처했다. 디자인 검사기의 단독 템플릿 색상 권고는 실제 기존 테마가 적용된 브라우저 확인과 구별한다. 새 CSS·색상·외부 모델은 추가하지 않았다.

독립 검토의 P2 두 건을 수정하고 재검토에서 차단할 P1/P2 없음으로 확인했다. 이 검증은 합성 자료이며 ROSY 배포·인증된 업무 근거·실물 운용 검증을 뜻하지 않는다.
