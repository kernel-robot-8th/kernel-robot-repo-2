# 연동 단계·오류 원인·다음 조치 검증

2026-10-26. Harbor 연동 설정의 진단·표시 개선이다. API 권한·장치 실행·운영 연결 수용을 변경하지 않는다. 기준 main은 `f990520a19749593d9334252f9b436a14b7c8d3d`이며 변경은 같은 PR의 코드와 설계25를 따른다.

## 확인한 동작

- 연결 설정·서비스 신원·작업 조회 API를 구분한다. 인증 후 ARM503인 경우 신원 성공을 유지하고 설치 담당자와 다음 조치를 표시한다.
- 실제 예외 형식으로 DNS·인증서·TLS·시간 초과를 구분하고, 원문 예외나 토큰을 노출하지 않는다. 알 수 없는 원인은 일반 연결 실패로 유지한다.
- 설정이 빠지거나 허용되지 않은 주소면 검사 버튼을 비활성화한다. 페이지 GET은 Fleet 통신·감사 쓰기·업무 명령 생성을 하지 않는다. 기존 권한·CSRF·설정 버전·fingerprint·원래 실행 identity 보호를 유지한다.
- 오류의 중복 메시지를 제거하고 모바일에서 다음 조치를 설정 폼보다 먼저 표시한다. 조회 검증과 실행 인계 설정·실제 실행 수용을 구분한다.

## 증거

회귀 시험 RED는11개 시험에서 기대한 실패6건을 확인했다. 구현 후 Django 전체201개가 통과했다. 브라우저 수용 도구 `tools/integration/fleet_bridge_browser_check.py`는 인증된 합성 HTTP double로 실제 웹앱을 검사한다. 실제 ROSY Fleet이나 실물 장치 시험을 뜻하지 않는다.

이번 변경의 Edge 브라우저 검증은1440·1280·768·390px 모두 가로 넘침 없이 PASS였다. 인증된 Fleet GET11개, 웹 GET의 Fleet 무통신, 관리자 전용 조작, 토큰의 HTML·감사 로그 비노출, Command0건을 확인했다. 실제 합성 HTTP503으로 부분 성공 표시를 검증했다. DNS 화면은 저장된 진단 fixture이며 실제 DNS 요청 실패를 브라우저에서 발생시킨 것으로 기록하지 않는다. DNS 분류 자체는 typed `socket.gaierror` 회귀 시험으로 확인했다.

390×844 화면에서 ‘다음 조치’ 제목의 y=711.875px로 첫 화면 안에 표시됨을 확인했다. 최종 로컬 근거는 `runs/readiness-browser-release/run-c1e95f88799a48768998cfd47f1cac39/report.json`이다. 필수 단위 시험은156개 실행 후 OK였으며 opt-in 실제 Fleet 통합 클래스1개는 건너뛰었다. 이를 실제 Fleet 실행으로 세지 않는다.

독립 검토에서 차단할 P1/P2 지적은 없었다. 디자인 검사기의 단독 템플릿 링크 색상 권고1건은 실제 앱에서 기존 팔레트가 적용되는 화면과 구별한다. 이번 변경은 새 CSS 색상을 추가하지 않는다.
