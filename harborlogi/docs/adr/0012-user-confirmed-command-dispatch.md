# ADR 0012: Harbor 사용자 확정과 즉시 실행 요청

날짜: 2026-10-26

상태: 제품 결정 수락. Harbor 즉시 제출 구현. ROSY의 추가 승인 없는 실행 계약은 후속 구현 필요.

## 결정

Harbor에서 실행 권한이 있는 사용자가 계획을 확정하는 행위가 업무 실행 지시다. 사용자가 이미 내린 결정을 별도 Fleet 화면에서 다시 내리도록 하는 것을 제품의 기본 흐름으로 삼지 않는다. LLM 또는 자연어 입력을 사용하더라도 동일한 지시 경로를 사용한다. 해석이 불명확한 입력은 대상·범위·영향을 확인하고, 확정된 지시만 전송한다.

목표 흐름은 **Harbor 사용자 확정 → 인증된 실행 요청 → ROSY admission → owner 실행 → 결과·근거의 Harbor 반영**이다. admission은 자원 점유·설치 조건·관측 신선도·권한·안전 검사를 뜻한다. 정상 조건에서 사람의 업무 결정을 다시 요구하는 단계가 아니다. 불가 조건은 이유와 가능한 다음 조치를 Harbor에 반환한다. 긴급 정지, 오류 후 복구, 설치 정책상 추가 검토가 필요한 예외는 명시적으로 표시한다.

자동 계획 생성이나 가상 배치 재생은 사용자 실행 확정을 대신하지 않는다. 실행 지시와 관측·물리 완료·업무 완료의 의미도 구별한다.

## 이번 구현과 현재 계약의 차이

기존 Harbor는 준비만 저장한 후 작업 화면에서 제출 버튼을 다시 눌러야 했다. 이제 계획 확정 POST에서 준비와 제출을 이어서 수행한다. 동일 계획의 재요청은 기존 Command를 열며, UNKNOWN이나 이미 제출된 작업을 다시 보내지 않는다. 타임아웃은 원래 요청 key로 대조한다. 관측·revision·설치 대응·역할 검사는 제출 직전에 유지한다.

현재 소비하는 ARM API는 제안 제출과 별도 운영자 승인을 요구한다. 이번 앱 변경으로 그 서버 정책을 제거하지 않는다. 화면은 이 제한을 표시하며, 즉시 제출을 물리 실행 시작으로 표시하지 않는다. ADR 0002·0004·0006의 별도 승인 서술은 현재 연결 계약의 설명으로 남기고, 제품 목표는 이 결정으로 대체한다.

## ROSY 계약 변경의 완료 조건

ROSY D-865는 사람이 정한 범위 안에서 Fleet 정책이 자동 승인한다는 방향을 제안한다. 현재 제안은 drive-only를 첫 범위로 삼고 팔 단계는 제외한다. 따라서 Harbor의 ARM 경로까지 이미 지원한다고 해석하지 않는다. 여기서 필요한 확장은 그 정책 범위와 ARM 계약의 별도 변경이다. Fleet의 admission 소유는 유지한다.

- Fleet에 설치된 승인 범위가 앱 서비스 신원, 대상 자원·작업 종류, 유효 기간·횟수 상한과 맞아야 한다. Harbor의 결정 사용자·계획 digest·revision은 추적 가능해야 하며, 사용자 위임을 실행 권한으로 사용하는 경우 ROSY가 그 신뢰 관계를 인증·검증해야 한다. 단순 actor 문자열이나 앱의 자체 승인 플래그를 믿지 않는다.
- ROSY가 설치 정책과 사용자 권한을 검사해 허용된 지시를 동일 요청에서 접수·admit한다. app 내부 import, 장치 직접 호출, 다른 운영자 자격을 숨겨 사용하는 방식은 채택하지 않는다.
- 동일 key·동일 본문은 원래 실행을 반환하고, key 본문 충돌·미인증 사용자·권한 부족·stale revision·자원 충돌은 명시적으로 거절한다. 응답 유실 뒤 새 key 재제출을 하지 않는다.
- 접수·대기·실행·보류·취소·결과 상태를 원래 업무에서 읽을 수 있어야 한다. 물리 receipt와 인증된 업무 근거까지 대조해야 완료다.
- 공개 API 명세·권한 시험·양 끝 HTTP 계약 시험을 함께 갱신한다. 정상 지시가 별도 화면 승인 없이 실행으로 진행하는 시험과 권한·자원·안전 거절 시험이 필요하다.

이 조건을 충족하기 전에는 전체 즉시 실행 파이프라인이 완성되었다고 보고하지 않는다. 현재 다칸 배치 실행은 설치 binding 미수용으로 보류되며 이 결정으로 활성화되지 않는다.
