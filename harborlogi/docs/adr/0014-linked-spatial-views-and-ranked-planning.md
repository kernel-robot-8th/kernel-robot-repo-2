# ADR 0014: 같은 공간 주소의 2D·3D 보기와 계산 기반 계획 추천

날짜: 2026-10-26

상태: 사용자 방향 수락, 구현·검증 진행. 기존 ADR0008·0010·0011·0013을 확장한다. ROSY 장치 실행·운영 설치 수용을 뜻하지 않는다.

## 결정의 배경

사용자는 층별 평면도와3D에서 동일한 화물·칸이 정확히 어디인지 확인하고, 계획 단계에서 AI 추천 또는 계산으로 더 나은 방법을 찾기를 요구했다. 현재 입고는 유효 후보의 순위를 계산하지만 공간 반출은 첫 번째 완전한 실행 가능 계획을 반환한다. 두 방식의 차이와 탐색 한계를 드러내고, 완전한 반출 계획끼리 비교한다.

## 1. 공간 주소와 보기의 단일 의미

화물의 주소는 설치 기준에 고정된 구역 ID,1부터 시작하는 행·열·층, 방향, 크기 원본과 전체 점유 영역으로 정의한다. 한 화물이 여러 칸을 점유해도 개체 하나다. ID 문자열이나 화면 나열 순서에서 좌표를 추측하지 않고 설정된 매핑을 사용한다.3D의 화면 배치 offset은 표시용이며 로봇 좌표나 구역 간 실제 이동 거리가 아니다.

각 배치 뷰어는 현재 기준(관측/계획 단계/로컬 가상 편집)과 선택 상태를 가진다.2D와3D는 같은 기준의 같은 선택을 공유한다.3D에서 화물을 고르면 해당 구역·층의 평면에서 전체 점유 영역과 주소를 표시한다.2D 화물 선택은3D 화물 선택·확대로 이어진다. 빈칸 선택은 빈 위치임을 명시한3D 표식을 보여주며 가짜 화물 개체를 만들지 않는다.

PC에서는 두 보기를 함께 비교하고 작은 화면에서는 같은 선택을 유지하며 전환한다. 관측·예상·가상 편집을 구별하며, 편집 중 평면을 관측 원본인 것처럼 덮어쓰지 않는다. 유효한 로컬 편집은 로컬 보기 양쪽에 반영하고 편집 종료/복원 때 고정된 기준으로 돌아온다. 선택·층 전환·카메라·재생·가상 편집은 서버 관측·Plan·Command를 쓰지 않는다. 키보드·reduced motion·무JS·WebGL 실패의 읽기 경로를 보존한다.

## 2. 추천은 검증된 계산부터 제공한다

이번 구현은 외부 AI 모델 없이도 작동하는 계산 추천이다. 기존 입고 순위 계산은 유지한다. 공간 반출은 현재 허용한 작업군(관련 상단 화물 임시 이동, 목표 반출, 재취급 화물 복귀; 방향 고정)에서 완전한 유효 계획을 비교한다. 임의 회전·무관 화물 이동·물리 경로·실행 시간을 추가로 발명하지 않는다.

이 작업군의 이동 수는 `2 × 재취급 개체 수 + 1`로 고정되므로, 이동 수만으로 후보의 우열을 주장하지 않는다. 첫 평가 기준 `restoration_lex_v1`은 다음을 우선순위대로 최소화한다.

1. 원래와 다른 구역으로 복귀하는 화물 수.
2. 원래와 다른 행·열로 복귀하는 화물 수.
3. 같은 구역 안에서 원래 위치와 복귀 위치의 행·열 Manhattan 차이 합계.
4. 복귀 화물의 최종 층 합계.
5. 동점일 때 완전한 이동 목록의 안정적인 주소 순서.

이 기준은 복귀 배치의 혼란을 줄이는 업무 목적이다. 다른 구역의 좌표를 빼서 로봇 이동 거리를 계산하거나, 층 합계를 실제 하중 안정성·작업 시간으로 표시하지 않는다. 물리 제약은 별도의 설치/실행 계약으로 검증한다.

선택 계획을 포함한 최대5개 비교 후보에 완전한 이동 목록·점수를 보존한다. 최초 유효 계획과 추천안의 차이도 설명한다. 평가 버전·비교 완료 계획 수·확장 상태 수·검사 위치 수·탐색 한도·종료 이유를 당시 Plan 결과에 고정한다. 화면 GET은 다시 계산하지 않는다.

입고의 우선 반출 방해 점수는 후보 바로 아래 열만 보지 않고 화물 전체의 지지 그래프를 따라간다. 여러 칸에 걸친 중간 화물을 통해 연결된 하부 화물도 중복 없이 포함한다. 이로써 후보 열 밖의 우선 반출 화물을 간접적으로 가두는 배치를 누락하지 않는다.

## 3. 탐색 한도와 최적이라는 표현

후보가 완전한지, 점유·전체 지지·도달성·허용 이동·원본 일치가 유효한지는 추천 점수보다 먼저 검사한다. 한도 내에서 비교한 최선이라는 표현을 기본으로 사용한다. 탐색이 완결됐다는 근거가 있을 때만 위에 정의한 제한된 작업군·평가 기준 안의 최선이라고 표시한다. 실제 로봇 경로나 모든 가능한 항만 업무의 전역 최적이라고 표시하지 않는다.

ADR0008의 한도 처리 결정을 보강한다. 한도에 도달할 때 완전한 유효 계획을 하나도 찾지 못했다면 이동 없는 HOLD다. 이미 완전하고 유효한 계획을 찾았다면 그중 최선의 전체 계획은 READY로 반환할 수 있으나 `search_complete=false`와 탐색 종료 이유를 보존하고 최적성 미확정으로 표시한다. 부분 경로를 READY로 반환하거나 제약 검사를 생략하지 않는다. READY는 실행 승인이나 예약이 아니다.

상태 재방문 가지치기는 평가 기준을 훼손하지 않아야 한다. 독립적인 작은 전수 탐색과 전체 이동 재생으로 최소 점수·유효성·동점의 결정성을 검증한다. 작은 고정 사례의 확장 상태·후보 수·결과·경과 시간을 기록하고 불안정한 wall-clock 임계값으로 정확성을 대신하지 않는다.

## 4. AI와 사람의 결정

계산 추천을 AI가 만든 결과로 표시하지 않는다. 향후 AI는 검증된 후보의 설명이나 후보 ID 제안을 할 수 있다. 새 배치/이동을 제안한다면 같은 원본·크기·점유·전체 지지·도달성·순서·완전한 복귀 검증을 통과해야 후보가 된다. 문장이나 모델의 자신감이 실행 가능성·우수성의 근거가 아니다. 현재 AI provider·token·외부 호출은 추가하지 않는다.

사용자는 계산 방법과 비교 결과를 확인해 계획을 확정한다. 목표 변경이나 확정 범위를 벗어나는 재계획은 별도 사용자 결정을 요구한다. 확정된 업무의 연속 운용은 ADR0013의 Harbor 실행기 책임이며 ROSY는 승인·자원·안전·장치 실행을 소유한다. 추천·보기 개선으로 미수용 실행 binding이나 ARM 정책을 활성화하지 않는다.

## 검증 기준

- 사용자2D 선택과3D 선택이 같은 구역/행/열/층/방향·전체 점유 주소를 표시한다. 빈칸은 위치 표식이며 화물 수가 늘지 않는다.
- 단계·원본·가상 편집 전환, 여러 칸 화물, 동시 보기·모바일·키보드·fallback에서 선택이 다른 배치와 섞이지 않는다. 원본 JSON/서버 쓰기0을 확인한다.
- 최초 성립안보다 점수가 나은 계산 추천 사례와 독립 전수 oracle, 대안의 전체 재생, 결정적 동점, 예산 전/후 소진, 기존 HOLD·실행 게이트를 확인한다.
- 추천 점수·대안·탐색 완료 여부가 저장되고 과거 Plan 조회 때 같은 의미로 보인다. 운영 Fleet·장치 수용은 별도 기록한다.
