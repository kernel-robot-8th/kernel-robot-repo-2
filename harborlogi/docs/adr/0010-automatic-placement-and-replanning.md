# ADR0010: 반출 순서를 고려한 자동 배치와 변경 기반 재계획

상태: 채택 (2026-10-26 사용자 요청). 구현·검증 결과는 별도 기록한다.

## 문제

Harbor의 목적은 수동 지도 편집이 아니라 입고 배치를 계산하고 반출 지시·관측 변화에 대응하는 것이다. 기존 `make_plan`은 입고를 `INBOUND_PLANNER_NOT_AVAILABLE`로 보류하고 반출만 계산했다. 변경 표시는 있지만 자동 재계산은 없었다.

## 결정

1. 순수 도메인 배치 계산은 관측된 전체 점유, 불변 화물 크기, 구역 역할·지지·도달 가능성과 반출 지시를 입력받는다. 유효 일반 보관 위치와0/90도 방향을 열거한다. 알려진 선출고 화물을 새로 막는 수, 순서 미확인 화물을 덮는 수, 높이, 고정 주소 순으로 결정한다. 이는 설명 가능한 결정적 휴리스틱이며 전체 일정 최적해·실측 시간 절감을 보장하지 않는다.
2. 배치 결과는 `grid-placement-v1`의 새 불변 Plan이며 추천 위치·방향·크기 원본·점수·후보 수·대안을 보존한다. 입고는 아직 관측된 내부 위치에 없으므로 가상의 source move를 만들지 않는다. 추천은 실물 이송 경로나 실행 허가가 아니다. 새 관측은 자동 생성하지 않는다.
3. 계획 폼에서 자동 재계획을 선택하면 요청에 관측 출처와 설치 기준을 명시적으로 결속한다. 기존 요청은 기본 해제하여 과거 검토가 묵시적으로 자동화되지 않게 한다. 등록된 지시의 생성/변경, 같은 출처 새 관측, 크기 revision 변경은 등록된 미인계 요청에 대해 새 Plan을 계산한다. 같은 입력에는 중복 자동 Plan을 만들지 않고 변경 원인·이전 계획·입력 식별자·결과 차이를 보존한다. GET 조회는 계획을 생성하지 않는다.
4. 다른 출처 관측으로 자동 전환하지 않는다. 같은 출처에서 설치 기준이 바뀌면 적용을 보류하고 명시적으로 재결속한다. 오래됨·holding·겹침·지지 부족·공간/도달 부족·탐색 한도는 설명 가능한 HOLD다. 새 Condition 등록 자체로 관측이나 활성 기준을 만들지 않는다.
5. 이미 Command가 있는 요청은 자동 재계획에서 제외한다. 접수/실행/결과 불명 상태의 원래 Plan·key·단계를 보존한다. 실행 중 요청의 나머지 단계를 자동 교체하는 것은 이번에 열지 않는다. 현재 실행을 대조하고 새 실제 관측이 확보된 후 미인계 요청을 계산한다. 다른 진행/불명 실행이 있으면 자동 제안을 보류할 수 있으나 취소·재접수·admit을 자동 호출하지 않는다.
6. 초기 서버는 기존 단일 writer와 재진입 직렬화 잠금 안에서 최대16개 자동 요청을 동기 계산한다.17번째 자동 등록을 명확하게 거절하고 작업을 조용히 누락하지 않는다. 도메인 후보·공간 상한도 유지한다. 다수 요청/시간 기반 재스케줄링이 필요해지면 영속 작업 큐와 별도 계산 worker로 옮기며, 현재 상한을 측정된 성능 수치로 표시하지 않는다.

## 입력의 의미

여러 자동 입고 요청은 요청 ID 순서로 앞선 유효 추천의 전체 점유를 계획상 예약으로 제외한다. 예약은 관측도, 아래층 지지도 아니다. 앞선 추천 변경은 뒤 요청의 입력 digest에 반영하여 연쇄 재계산한다. 실제 입고를 관측하면 해당 예약을 별도로 중복 적용하지 않는다. 미래 화물을 지지로 쌓는 다단계 입고 최적화는 수행하지 않는다.

현재 Command 상태만으로는 업무 전체 완료·공간 해제가 입증되지 않는다. 다른 Command 이력이 있으면 자동 계산을 보수적으로 보류한다. 실행 중 요청뿐 아니라 과거 인계 이후의 자동 재개도 인증된 완료·새 관측 연결을 수용하기 전에는 열지 않는다. 담당자의 명시적 관측 선택과 직접 검토는 별도이며 기존 실행을 수정하지 않는다.

스케줄은 현재 명시된 반출 우선순위 그룹과 고정 순서 또는 같은 그룹 선택 허용이다. 입고 지시의 우선순위를 반출 예정 순서로 간주하지 않는다. 해당 화물의 반출 지시가 없으면 순서 미확인으로 표시하고 알려진 선출고 화물을 덮는 배치를 피한다. 장비 가용성·구역 제한은 결속된 설치 기준과 관측으로만 판단한다. 실시간 ETA·벽시계 일정·속도 추정·장비 고장 이벤트 연동은 입력 계약과 실제 수용 없이 생성하지 않는다.

## UI와 경계

입고 요청과 계획에는 자동 배치 계산, 추천 위치/방향과 점수, 관측·예상3D/평면, 이전 추천 대비 변경 이유를 제공한다. 반출도 동일한 자동 재계획 설정과 이력을 표시한다. 자동 계산 상태와 ROSY 인계·실제 실행 상태를 분리한다. `SPATIAL_EXECUTION_BINDINGS_REQUIRED`와 별도 독립 승인·업무 근거 조건은 유지한다.

## 수용

반출 순서 역전 시 배치 후보 변경, 다칸 지지·겹침·회전·도달, 순서 미확인, 오래된 관측, 전체 만석, 동일 입력 중복, 다른 출처 무시, 설치 기준 변경 보류, 실행 중 원본 불변, 자동 요청 상한을 검증한다. 실제 브라우저에서 입고 추천과 지시 변경/새 관측 뒤 새 계획·이전 기준 보존을 확인한다. 실물/성능 수용은 소프트웨어 시험과 구분한다.
