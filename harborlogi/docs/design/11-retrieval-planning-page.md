# 제품 흐름과 재고·반출 계획 페이지

2026-10-25 사용자 요청: Harbor의 사용자 결과와 시스템 동작을 기준으로 앱을 구성한다. 요구사항 정본 대조는 팀 내부 작업 기록에 보존하며 공개 저장소에 원문 표를 복사하지 않는다. 아래 구현은 기존 공개 [CONTEXT](../../CONTEXT.md), ADR0005와 `model/outbound`의 범위다.

Harbor의 중심은 양하 이후 장치된 화물의 반출 지시가 달라졌을 때 재취급을 동반해 목표를 꺼내고, 재취급 화물을 복귀시키고, 완료 근거를 대조하는 흐름이다. 현재 운영 현황/업무 장부 조회는 그 일부이며 입고 요청·순위 지시·재고 관측·실제 실행/완료·이력·비교 전체를 구현한 앱은 아니다.

## 이번 구현

- `/planning`에 **합성 재고·반출 계획**을 추가한다. demo에서만 메뉴를 제공하고 실제 모드에서는 source 없음으로 명확히 거절한다.
- 관측 장치 칸의 화물·단과 계획 후 예상 결과를 분리한다. 합성 시각·source·revision·합성 도달 표임을 표시한다.
- 반출 대상과 합성 조건을 선택하고 기존 `plan_outbound`를 서버에서 실제 호출한다. JS에 성공 계획을 하드코딩하지 않는다.
- 정상·임시 공간 부족·오래된 관측 시나리오에서 READY/HOLD와 이유를 보여 준다. HOLD에는 부분 이동이나 예상 완료 배치를 만들지 않는다.
- 이동을 재취급/반출/복귀로 구분하고 주/대체 팔을 표시한다. 이는 계획이며 실행 배정·관측 사실·양팔 비교 결과가 아니다.
- 필요한 완료3요소를 보여 주되 모두 실제 근거 확인 전이다. 생성/제안/승인/실행/강제 완료 쓰기는 없다.
- 단일 목표 preview이며 출고 순위/동순위 규칙 접수·검증·저장, 실제 관측 adapter, 화물 기본 정보 등록, 입고, 중단·복구, 전 구간 이력·비교는 후속이다.

## 작업 순서

- [x] fixture adapter·실제 planner 호출·HOLD 무부분계획·관측 불변·live source 미설정·GET 경계를 시험한다.
- [x] 조회 API와 페이지를 구현하고 기존 토큰·네비게이션에 연결한다.
- [x] 관측과 예상 배치, 재취급→반출→복귀, 입력 변경/불명/실패 상태를 브라우저에서 확인한다.
- [x] 전체 unittest·생성 CSS·기존 탐색 회귀·원본 유지·독립 검토 후 [결과](../validation/2026-10-25-retrieval-planning.md)를 기록한다.

이 보강은 사용자 결과에 가까운 계획 기능을 실제 화면에 연결하는 단계다. 합성 계획을 실제 재고/출고 지시 또는 UR/SR 전체 수용으로 표시하지 않는다. 임의 개선율, 성공 건수, 실제 재취급 횟수나 사람 개입0을 채우지 않는다.
