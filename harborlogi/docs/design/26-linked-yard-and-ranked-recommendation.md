# 2D·3D 공통 공간 보기와 계산 추천

2026-10-26. 결정 정본은 [ADR0014](../adr/0014-linked-spatial-views-and-ranked-planning.md)다. Harbor의 UI·계산 구현이며 ROSY의 실행 승인·자원·장치 제어와 구별한다.

## 같은 화물·같은 위치를 확인하는 흐름

관제 PC에서는3D 모델과 층별 평면을 함께 표시한다. 작은 화면에서는 보기를 전환하면서 같은 선택을 유지한다. 선택된 개체/위치의 구역·행·열·층·방향·전체 점유 주소를 표시한다.2×1·3×1도 하나의 화물이고 평면에서 여러 개로 쪼개지지 않는다.

| 사용자 조작 | 두 보기의 결과 |
|---|---|
| 3D 화물 클릭·화물 목록 선택 | 해당 개체와 전체 점유 주소 선택, 평면의 해당 구역·층 표시 |
| 평면 화물 클릭·키보드 선택 | 같은 화물을3D에서 선택하고 주소·크기 원본 확인 |
| 관측된 빈 위치 선택 | 동일 좌표의 점선 위치 표식과 주소. 화물 수를 늘리지 않음 |
| 점유를 관측하지 않은 설치 맵 선택 | ‘미관측 위치 · 점유 확인 안 됨’. 빈칸으로 단정하지 않음 |
| 계획 단계 변경 | 선택 개체를 해당 단계의 위치로 연결. 선택 위치에 화물이 들어오면 점유 개체로 연결 |
| 가상 편집 | 로컬 배치를 두 보기에 반영하고 ‘가상 편집’으로 표시. 종료·복원 시 기준 배치로 복귀 |
| 애니메이션 중 모바일 보기 전환 | 선택 단계의 끝점으로 정리해 평면과3D가 중간/최종 위치로 어긋나지 않음 |

위치는 설정된 행·열 대응에서 가져온다. 화물 ID나 `Y11` 같은 표기의 글자를 잘라 좌표를 추측하지 않는다.3D 구역 간 간격은 표시용이고 로봇 좌표가 아니다. 각 뷰어의 선택 이벤트와 상태는 그 뷰어에만 속한다. 원본 JSON을 바꾸거나 웹 요청으로 관측/Plan/Command를 쓰지 않는다.

JavaScript가 없거나 WebGL이 실패하면 서버가 만든 원본 층별 평면을 읽는다. 미관측 맵, 원본 관측, 계획 뒤 예상, 로컬 가상 편집을 같은 데이터로 취급하지 않는다. 기존 느린 재생·reduced motion·카메라·전체 화면·편집 기능을 보존한다.

## 무엇을 계산해 추천하는가

입고 후보는 순위가 앞선 반출 화물과 순서 미확인 화물을 얼마나 가두는지, 배치 층을 비교한다. 중간의 다칸 화물이 다른 열의 화물을 지지하고 있으면 그 지지 관계도 따라가야 한다. 후보 바로 아래 열만 보는 방식은 이 간접 방해를 놓치므로 전체 지지 그래프로 보강했다.

공간 반출은 첫 성립안으로 멈추지 않고 완전한 유효 계획을 비교한다. 현재 허용한 작업군의 이동 수는 모두 `2×재취급 개체 수+1`이므로 이동 수를 줄였다고 주장하지 않는다. 평가 버전 `restoration_lex_v1`의 순서는 다음과 같다.

| 우선순위 | 최소화하는 값 | 의미 |
|---|---|---|
| 1 | 복귀 구역 변경 개체 수 | 원래 구역에 돌려놓기 |
| 2 | 복귀 행·열 변경 개체 수 | 원래 가로 위치를 유지하기 |
| 3 | 같은 구역의 행·열 주소 차이 합계 | 위치가 달라지면 원래 주소와 가까운 논리 위치 |
| 4 | 복귀 화물의 층 합계 | 앞 지표가 동점일 때 낮은 논리 배치 선호 |
| 동점 | 전체 이동의 안정적인 주소 순서 | 같은 입력에서 같은 결과 |

앞 지표를 먼저 비교하므로 층 합계만 작다고 더 좋은 후보는 아니다. 실제 시험 사례에서 첫 성립안은 `(0,1,1,2)`, 추천은 `(0,0,0,3)`이었다. 층 합계가 커져도 복귀 행·열 변경을1개에서0개로 줄여 우선순위에 맞는 추천이다. 이 값은 로봇 이동 거리·물리 작업 시간·실물 적층 안정성 점수가 아니다.

## 탐색 한도와 설명 화면

추천 Plan에는 평가 버전, 점수, 첫 성립안 점수, 추천 포함 최대5개 후보의 전체 이동, 비교한 완전 계획 수, 검사 상태/위치 수와 한도를 고정한다. 비교 화면을 읽는 GET에서 다시 계산하지 않는다. 과거 Plan에 평가 자료가 없으면 원래 계획과 자료 없음 안내만 보여준다.

탐색을 마쳤으면 정의한 제한 작업군과 평가 안의 비교 완료로 표시한다. 예산이 끝났지만 완전한 유효 계획을 찾았으면 ‘탐색 한도 내 추천’으로 표시한다. 그 경우 최적성을 확정하지 않는다. 완전한 계획을 찾지 못했으면 이동 없는 HOLD다. 대안에도 전체 점유·지지·팔 도달성·허용 이동·복귀가 유효해야 하며 부분 경로를 추천하지 않는다.

화면은 첫 성립안과 추천안의 각 지표를 나란히 보여주고, 후보의 전체 이동과 탐색 원본을 펼쳐볼 수 있게 한다. 계산 추천은 사용자 확정 전의 제안이며 실제 자원 예약이나 실행 승인이 아니다.

## AI와 연속 업무 운용

현재 구현은 외부 AI 없이 결정적으로 계산한다. AI 모델의 출력을 꾸며 표시하지 않는다. 향후 AI는 검증된 후보 설명이나 후보 ID 제안을 할 수 있으며 새 배치를 제안하면 같은 제약 검증·완전 경로 replay를 통과해야 한다. 사용자 확정과 ROSY의 승인·안전 권한을 대신하지 않는다.

Harbor 상시 업무 실행기는 [설계24](24-business-execution-boundary.md), Fleet 설정·검사는 [설계25](25-fleet-connection-bridge.md)를 따른다. 운영 ARM 설치·서비스 발급·장부 복구와 실물 수용은 이 UI·추천 변경과 별도로 검증한다.
