# 컨테이너 배치와 이동 순서의 3D 보기

mode: Operate. 기존 HarborLogi 브랜드·의미 토큰을 계승한다. 입체 보기의 목적은 화물의 길이·적층·재취급 순서를 이해하는 것이다.

사용자 요청: 칸별 숫자·평면도만으로 이해하기 어려운 컨테이너 배치를 입체 박스와 이동 설명으로 보여준다. 기존 Django/브랜드/원본·계획·실행 경계를 유지한다.

3D 보기는 기존 야드 stage read model의 명시한 행·열·층·colspan/rowspan을 사용한다. 2×1·3×1은 박스 하나이며 복제하지 않는다. 원본에 없는 좌표·실측 크기·방향은 추측하지 않는다. yard layout이 없는 원본은 기존 위치 목록을 제공한다. 보조 구역을 나란히 놓는 화면상 간격은 논리 배치이며 현장 좌표가 아니다.

브라우저 Canvas에서 실제3차원 좌표를 카메라 회전·기울기·확대로 투영한다. 외부3D 엔진/CDN을 추가하지 않는다. 기본은 전체 배치를 보는3D이며 동일 원본의 층별 평면도로 전환한다. JS/Canvas 미지원 때 원래2D 조회가 유지된다. 박스 클릭/키보드 선택 목록은 ID·크기·위치를 보여주며 위치 편집은 없다.

사용자가 계획 재생을 시작하면 관측→재취급→반출→복귀 stage와 기존 단계 버튼을 동기화한다. 박스를 들어 올리고 옮겨 내려놓는 애니메이션은 순서 설명용이며 실제 로봇 경로나 실행 상태가 아니다. 자동 재생은 없고 중지/단계 변경·페이지 숨김·동작 줄이기를 존중한다. GET/재생/회전/선택은 서버 쓰기·Fleet 요청·업무 완료를 만들지 않는다.

수용: 같은6개 화물과2×1/3×1/90도 방향, 관측과 예상 배치 구분, 박스 선택·회전·재생·평면도 동기화·원본 불변,4화면 폭·noJS·reduced-motion·CSP/console 오류·Canvas 미지원 복구를 검증한다.
