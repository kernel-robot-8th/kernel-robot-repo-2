# 반출 업무 작업 공간

상태: 2026-10-25 구현 기준. 사용자의 ‘그럼 완성을 시켜볼래?’는 직전 제안한 반출 업무 작업 공간의 구현을 승인한 요청으로 해석한다. 기존 PC 관제·태블릿 보조·Django·HarborLogi 로고와 토큰을 유지한다.

## 목적과 완료 기준

변경된 반출 지시를 받은 관제자가 대상 화물, 방해 화물, 허용 임시 위치, 이동 순서와 팔 역할을 검토하고, ROSY에 인계한 원래 실행과 업무 완료 근거를 같은 업무에서 대조한다. 입고는 이 흐름에 재고를 공급하는 별도 업무이며 반출 planner로 대체하지 않는다.

전용 반출 목록은 지시된 그룹·허용 순서와 다음 조치를 보여 준다. 요청 상세와 고정된 계획 상세가 같은 작업 공간을 사용한다. 작업 공간은 야드·계획, 실행·근거, 변경 이력으로 이동하며 계획 생성·우선순위 변경·기존 실행 대조는 기존 권한/CSRF/version/중복 방지 서비스를 그대로 사용한다.

## 정보와 화면

- 첫 영역: 화물·요청 revision·우선순위·업무 판단 상태. 상태는 계획 READY와 실제 완료를 구별한다.
- 주 영역: 원본 관측의 장치 칸·임시 칸·반출대. 목표와 재취급 화물을 글자와 형태로 구별한다. 기하 좌표·실측 배치도로 주장하지 않는 논리 배치다.
- 단계 선택: 기준 관측과 각 이동 뒤 예상 배치를 선택한다. JavaScript는 이 미리보기만 전환하며 관측·장부·실행을 쓰지 않는다. JS가 없어도 원본·최종 예상·모든 이동 순서를 읽을 수 있다.
- 옆 영역: 지금 필요한 판단, 최신 지시/관측과 계획의 차이, 원본 선택·계획 생성. 실제 인계가 있으면 원래 실행을 우선한다. 과거 계획은 현재 지시로 재해석하지 않는다.
- 실행·근거: 웹 제출 상태, 읽기 전용 업무 장부, 원래 mission, 현재 단계와 receipt. 반출대 배치·재취급 복귀·관련 팔 퇴피의 인증된 업무 근거가 없으면 완료 미확인이다. receipt나 계획 그림으로 이를 채우지 않는다.
- 변경 이력: 해당 요청·계획·실행의 감사 기록과 계획 생성 시 지시 원문. 다른 업무의 감사는 섞지 않는다.

## 경계와 검증

새 middleware/장치 API·producer·자동 승인·확인 bool을 만들지 않는다. 인증된 관측/완료 producer와 모든 이동의 설치 binding이 없으면 운영 다단계 실행은 계속 막힌다. 현재 지원된 단일 ARM 제안·조회·취소 계약을 유지하며 임의 다음 단계나 완료 버튼을 추가하지 않는다. 운영 준비 결손은 담당 영역과 연결 화면으로 노출한다.

검증은 서버의 권한/원본 결속/상태 표기/GET 무변경/계획 신선도/업무 이력 격리와 브라우저의 실제 단계 전환·폼·키보드·네 가지 폭·오류/오버플로를 포함한다. 합성 미리보기의 통과는 로봇·카메라·현장 수용을 뜻하지 않는다.
