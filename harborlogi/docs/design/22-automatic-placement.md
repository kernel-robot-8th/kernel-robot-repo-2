# 자동 입고 배치와 변경 기반 재계획

[ADR0010](../adr/0010-automatic-placement-and-replanning.md)이 결정의 정본이다. 수동 맵/화물 편집은 계산 결과를 검토하는 보조 도구다.

## 사용 흐름

입고 요청에서 관측 출처·설치 기준을 확인하고 ‘지시·관측이 바뀌면 자동 재계획’을 선택해 ‘입고 배치 자동 계산’을 누른다. 추천 위치·방향·점유 크기 revision, 유효 후보 수·점수·대안을 확인한다. 관측/추천을3D·평면으로 전환할 수 있다. 반출 요청도 동일한 폼에서 자동 재계획을 등록할 수 있다. 해제한 뒤 계산하면 이후 자동 재계산을 중단한다.

이후 지시 생성/수정, 결속한 출처의 새 관측, 화물 크기 revision 변경, 앞선 입고 추천 변경에 새 Plan을 만든다. 화면은 변경 원인과 이전 계획 링크를 보여준다. 과거 URL을 열면 당시 위치와 크기를 계속 읽을 수 있다. GET 조회는 계산·관측·명령을 생성하지 않는다.

## 계산과 입력

- 기존 일반 보관 구역의 행·열·층과 화물1×1/2×1/3×1,0/90도 방향을 검사한다. 전체 경계·겹침·아래 지지·동일 팔의 전체 목적 위치 도달 조건을 충족하는 후보만 비교한다.
- 추가로 막는 선출고 화물 수 → 순서 미확인 관계 수 → 층 → 구역/행/열/방향의 고정 순서로 고른다. 해당 화물의 반출 지시가 없으면 미확인으로 표시한다. 입고 지시 순위를 반출 순위로 쓰지 않는다.
- 앞선 자동 입고의 추천 영역은 계획상 예약으로 제외한다. 추천 화물을 실제 점유나 아래층 지지로 만들지 않는다. 이전 추천 원본을 입력 digest에 포함하여 뒤 요청을 연쇄 재계산한다.
- 입력 digest에는 지시, 선택/새 관측, 원래 source/condition binding, 정책·크기 원본, 관련 계획상 예약·Command 상태를 포함한다. 같은 입력의 자동 이벤트에는 새 Plan을 중복 생성하지 않는다.
- 기존 요청은 자동 설정 기본 해제다. 명시적으로 켠 요청 최대16개를 기존 단일 writer·직렬화 트랜잭션으로 처리한다. 후보·공간·화물 수 상한은 유지한다. 수치는 실물 성능 보장이 아니다.

## 보류와 실행 경계

오래됨·holding·미관측 크기·불가 배치·검색 한도는 추천 없는 HOLD다. 다른 producer의 관측은 무시하고, 같은 producer에서 Condition이 바뀌면 명시적 재결속 전까지 보류한다. Command가 있는 요청은 자동 교체하지 않는다. 다른 Command 이력은 현재 상태만으로 업무 완료와 공간 해제가 입증되지 않아 자동 재계산을 보수적으로 보류한다.

실행 중 요청의 남은 단계를 자동 수정하거나 Fleet 취소/재제출/admit을 호출하지 않는다. 인증된 업무 완료·새 관측 기반 자동 재개, 실시간 고장/ETA·시간표 최적화와 영속 대규모 계산 worker는 후속 입력·수용 계약이 필요하다. 현재 기능은 지시 순서와 관측 변경에 반응하는 결정적 제안 계산이다.

## 사용자 요구의 공개 구현 추적

팀 UR/SR 원문·상태는 비공개 정본에 있으며 아래는 구현 범위의 추적이다.

| 사용자 결과 | 시스템 동작 | 확인 |
|---|---|---|
| 먼저 반출할 화물을 고려해 입고 위치를 고른다 | 전체 footprint 후보와 추가 선출고 방해 수를 비교 | 순서 역전 시 추천 칸 변경·도달/지지/회전 단위 시험 |
| 지시·실제 배치가 바뀌면 다시 계산한다 | 명시적 자동 설정, 이벤트마다 새 불변 Plan | 실제 UI 지시 변경·새 관측 등록 뒤 자동 변경 |
| 여러 입고 추천이 같은 칸을 쓰지 않는다 | 앞선 계획상 예약 제외·변경 전파 | 복수 입고·크기 변경 뒤 재배치·가상 지지 거절 |
| 계획과 실제 수행을 혼동하지 않는다 | 원본·예상 장면 분리, Command 불변·자동 제출 없음 | GET 무부작용·과거 크기/배치·출처/기준·권한·명령0건 확인 |
